# 四年级上册生字复习工具设计规格

- 日期：2026-11-06
- 状态：已通过
- 产品形态：可添加到 iPad/iPhone 主屏幕的静态 Web 应用
- 适用教材：统编版义务教育教科书·语文四年级上册（根据 2022 年版课程标准修订，2024 年审核）
- 发布方式：GitHub Pages
- 数据与判定：全部在浏览器本地完成，不上传笔迹，不需要账号或后端

## 1. 产品目标

为小学四年级学生提供一个按课复习生字的工具。学生可以选择课目，在“认读”和“书写”之间切换：

- 认读显示汉字，点击后显示拼音并播放读音；
- 书写显示拼音，学生在田字格内手写完整汉字；
- 提交整字后，同时检查字形、笔顺和每一笔的书写方向；
- 出错时播放标准笔顺动画，由学生选择“再写一次”或“先跳过”；
- 跳过或写错的字进入本课错字回顾；
- iPad 和 iPhone 均提供完整功能，并各自在本机保存进度。

产品的核心不是通用手写 OCR，而是“已知目标字的限定式笔迹比对”。题目始终知道正确答案，因此可以可靠检查笔画数量、顺序、方向、位置和形状，而不需要把笔迹上传到识别服务。

## 2. 非目标

本版本不包含以下能力：

- 不识别任意汉字或学生想写的任意内容；
- 不做作文、听写或整句 OCR；
- 不提供教师端、班级管理、账号登录或跨设备同步；
- 不上传、保存或分析原始笔迹、截图和手写轨迹；
- 不使用 NAS 容器、数据库或自建后端；
- 不把教材扫描页作为产品素材分发；
- 不自动播放背景音乐，也不在页面加载时自动朗读。

## 3. 教材与题库

### 3.1 数据来源

教材数据以国家中小学智慧教育平台提供的电子教材为准：

- 平台：国家中小学智慧教育平台
- 出版社：人民教育出版社
- 教材 ID：`5cd7e623-5c38-4602-871a-3fba8a551db2`
- 电子书 ID：`1cea417b-ba9c-44b7-b7c1-db53a962f2d4`
- 详情页：`https://basic.smartedu.cn/tchMaterial/detail?contentType=assets_document&contentId=5cd7e623-5c38-4602-871a-3fba8a551db2&catalogType=tchMaterial&subCatalog=tchMaterial`

教材扫描页仅用于整理和核对，不进入生产包。产品中只保留课目名称、单元、表类型、汉字、拼音、多音字标记和笔顺所需的结构化数据。

### 3.2 内容规模

题库必须满足以下固定校验：

| 项目 | 数量 |
| --- | ---: |
| 课文 | 27 课 |
| 语文园地 | 4 个 |
| 总分组 | 31 个 |
| 识字表练习条目 | 265 个 |
| 识字表中计数生字 | 250 个 |
| 识字表蓝色多音字条目 | 15 个 |
| 写字表练习条目 | 250 个 |
| 两表去重后的目标汉字 | 413 个 |

识字表中有 264 个不同汉字，因为“脏”以 `zāng` 和 `zàng` 两个读音分别出现。合并两表后共有 413 个不同目标汉字。全部目标字都必须具备标准笔画数据。

语文园地按教材位置插入：

- 语文园地二：第 7 课后；
- 语文园地四：第 14 课后；
- 语文园地六：第 19 课后；
- 语文园地七：第 23 课后。

### 3.3 结构化字段

每个分组使用稳定 ID，例如 `lesson-1`、`lesson-2`、`garden-2`。生产数据至少包含：

```ts
type PracticeItem = {
  char: string;
  pinyin: string;
  polyphone: boolean;
  speechText?: string; // 仅多音字需要，用于降低 TTS 读错概率
};

type ContentGroup = {
  id: string;
  kind: "lesson" | "garden";
  unit: string;
  title: string;
  lessonNo?: number;
  sourcePage: number;
  reading: PracticeItem[];
  writing: PracticeItem[];
};
```

拼音以教材识字表或写字表标注为准，不依赖浏览器自动注音。必须保留已经人工核对的多音字读音，包括但不限于：`降 xiáng`、`铺 pū`、`重 zhòng`、`脏 zāng/zàng`、`着 zhuó`、`率 shuài`、`肖 xiào`、`畜 chù`、`露 lòu`、`哄 hōng`、`塞 sài`、`将 jiàng`、`俩 liǎ`。

蓝色多音字条目在 UI 中显示“多音字”标签。多音字的 `speechText` 使用能自然带出目标读音的短词；无多音字冲突时直接朗读目标汉字。

### 3.4 书写来源规则

书写模式提供三个来源，默认选择“仅写字表”：

1. **仅写字表**：严格使用当前分组的 `writing` 条目，保持原顺序。
2. **仅识字表**：使用当前分组的 `reading` 条目，保持原顺序；蓝色多音字条目属于有效练习条目，不能遗漏。
3. **两表都有**：先取识字表顺序，再追加写字表中尚未出现的汉字；按 `char` 首次出现去重，保持首次出现位置。

当当前分组的写字表为空时，例如略读课文，界面必须明确提示“本课没有写字表内容”，并自动切换到“仅识字表”。切换结果要可见，不能静默跳过。

每个来源选项显示实际条目数，例如“仅写字表 · 12 字”。条目数为 0 的选项禁用。

## 4. 页面与练习流程

### 4.1 页面结构

应用使用 Hash 路由，避免 GitHub Pages 的静态路径回退问题。主要路由为：

- `#/`：首页与课目选择；
- `#/lesson/:groupId/read`：该课认读练习；
- `#/lesson/:groupId/write`：该课书写练习；
- `#/lesson/:groupId/summary`：本次练习结果。

练习页顶部始终提供“认读 / 书写”分段切换，并保留当前课目。返回首页后保留最近选择的课目和模式。

### 4.2 首页与课目选择

首页包含：

- 产品标题与“小桃猫”吉祥物；
- “继续最近练习”入口；
- 按单元分组的 27 篇课文和 4 个语文园地；
- 每课显示可练习的识字表、写字表条目数；
- 本地进度概览：已完成条目、待复习错字。

iPad 横屏使用左侧课目栏和右侧内容区；窄屏使用全屏课目列表。选择课目后进入默认模式“认读”。

### 4.3 认读模式

认读固定使用当前分组的识字表：

1. 一次显示一个汉字，不提前显示拼音；
2. 点击汉字卡片后显示拼音、多音字标签和喇叭按钮；
3. 同一手势触发一次读音播放；再次点击喇叭可重播；
4. 卡片下方提供“还不熟”和“认识”两个操作；
5. “还不熟”记入待复习列表，“认识”记入已掌握；
6. 全部完成后显示本课认读结果，并可选择再练待复习字或返回课目。

页面同时显示当前序号和进度条，不显示下一个字的答案。

### 4.4 书写模式

进入书写模式后：

1. 展示书写来源选择器和当前来源的条目数；
2. 一次显示一个拼音，不显示目标汉字；
3. 多音字显示对应标签，确保学生知道要写的读音；
4. 中央显示空白田字格；
5. 学生可用手指或触控笔连续书写多笔，所有笔画作为整字暂存在内存；
6. “提交”只在至少有一笔时可用；
7. 学生可以“清空重写”，但清空不产生判定和进度记录。

提交后不允许再修改本次笔迹，直接进行整字判定。

### 4.5 判定结果与错误流程

判定结果只有三种：

- **正确**：进入轻柔的成功反馈，记录正确，约 0.8 秒后或点击“下一字”继续；
- **有误**：显示明确原因，例如“笔画顺序不对”“这一笔方向反了”“字形或笔画数量不对”，随后自动播放标准笔顺动画；
- **识别不清**：提示“小桃猫没看清，请再写清楚一点”，允许清空后重写，不计为答错。

判定为“有误”并播放笔顺动画后，必须提供两个按钮：

- **再写一次**：清空田字格，继续同一字；
- **先跳过**：把当前字加入本课错字列表并进入下一字。

错误提交和跳过都记录错误次数；之后的正确重写不会抹除“曾经出错”的历史，但在本次结果中标记为已订正。识别不清和主动清空不增加错误次数。

一次练习结束后显示：

- 本次正确数；
- 本次跳过或需复习数；
- 本课错字列表；
- “再练错字”和“返回课目”入口。

## 5. 手写判定与隐私

### 5.1 输入采集

书写区使用 Pointer Events，统一处理 Apple Pencil、手指和 iPhone 触控：

- 书写区设置 `touch-action: none`，避免笔画触发页面滚动或缩放；
- 只禁用田字格区域的浏览器手势，页面其他区域仍可正常滚动；
- 使用 Pointer Capture，防止手指移出格边时断线；
- 每个笔画保存归一化折线点序列，提交前只保存在组件内存；
- 取消、切页或刷新后丢弃未提交笔迹，不写入 `localStorage`；
- 屏幕旋转或尺寸变化时，按归一化坐标重绘已有笔迹，不改变笔顺和相对位置。

### 5.2 判定输入与输出

判定器以“目标字标准笔画数据 + 学生整字笔迹”为输入。标准数据采用 Hanzi Writer 字符数据中的 `medians` 和 `strokes`。判定器返回：

```ts
type Verdict = "correct" | "incorrect" | "unclear";

type ErrorReason =
  | "stroke_count"
  | "stroke_shape"
  | "stroke_order"
  | "stroke_direction"
  | "ink_quality";

type Evaluation = {
  verdict: Verdict;
  reasons: ErrorReason[];
  confidence: number;
};
```

原始判定详情只用于当次界面反馈，不持久化。

### 5.3 整字判定顺序

整字判定不是逐笔即时判题，而是在学生点击“提交”后一次性执行：

1. 删除重复采样点，过滤过短的意外触点；
2. 将学生笔迹与标准字映射到同一 1024×1024 字符坐标系；
3. 检查笔画数量和每条笔迹的有效采样长度；
4. 将学生笔迹与目标字的同序号笔画比较；
5. 若同序号不匹配，再将笔迹与所有目标笔画比较，以区分“笔顺错”和“字形错”；
6. 对错误笔迹反向重试，以区分“方向反”和“形状错”；
7. 检查所有笔画组合后的整体位置、比例和覆盖范围；
8. 生成“正确 / 有误 / 识别不清”及具体原因。

单个笔画对比同时检查：

- 平均点线距离；
- 起笔点和收笔点位置；
- 线段方向一致性；
- 去尺度后的曲线形状；
- 长度比例。

起点、终点和平均距离采用与 Hanzi Writer 笔画判定相同的 1024 坐标尺度作为初始基线；平均距离阈值 350、起终点阈值 250、曲线形状阈值 0.4、最小长度比例 0.35。阈值集中在独立配置中，并用测试样本校准，不能散落在 UI 组件里。

### 5.4 错误分类优先级

判定按以下优先级输出主要错误：

1. **识别不清**：采样点太少、笔迹过短、严重越界、有效墨迹覆盖不足，或多项指标接近阈值。
2. **笔画数量错**：数量与标准字不同，且笔迹本身清楚。
3. **笔顺错**：某笔的形状与另一条目标笔画高度匹配，但位置序号不对。
4. **方向错**：当前笔正向不匹配，但反向通过形状与起终点检查。
5. **字形错**：笔画数量相同，但某笔无法匹配任何目标笔画，或整字比例、位置明显不符。

只有“正确”状态要求同时满足：笔画数量正确、每条笔画顺序正确、每条笔画方向正确、所有笔画形状与位置在容差内。宁可提示“再写清楚一些”，也不要把无法确认的笔迹直接判为错误。

### 5.5 标准笔顺动画

标准笔顺动画使用 Hanzi Writer 和中文字符笔画数据，按标准笔画顺序逐笔绘制。它只在以下时机播放：

- 判错后的反馈阶段；
- 用户主动点击“播放笔顺”。

书写答题阶段不显示完整目标字，也不显示描红轮廓，避免泄露答案。

### 5.6 已知限制

- 极草、连笔严重或笔画明显粘连的书写可能被判为“识别不清”，而不是错误；
- 田字格内文字过小、越界超过可校正范围或只写局部时，会要求重写；
- 判定针对教材标准楷体结构，不评价书法风格；
- 正式发布前必须在真实 iPad 和 iPhone 上完成触控校准。

## 6. 读音播放

优先使用浏览器内置的 Web Speech API：

- 使用 `SpeechSynthesisUtterance`，语言设置为 `zh-CN`；
- 只在用户点击后播放，页面加载不自动发声；
- 播放前取消尚未结束的队列，避免连续点击叠音；
- 语速设置为较慢的教学语速，约 `0.75`；
- 普通字直接朗读汉字，多音字朗读经过人工挑选的 `speechText` 短词；
- 播放按钮同时显示文字标签，不只依赖喇叭图标。

如果设备没有中文语音、语音服务出错或用户关闭朗读：

- 拼音仍正常显示；
- 显示“此设备暂时无法播放读音”；
- 提供“再试一次”；
- 不阻塞认读和书写练习。

实现不得依赖外部 TTS 接口，也不得因离线状态使认读流程失效。

## 7. 视觉设计

### 7.1 风格方向

整体为温柔、清爽、有陪伴感的女孩向视觉，甜美但不幼稚。学习内容始终是视觉中心，猫咪只承担引导、鼓励和错误提示，不遮挡汉字或田字格。

### 7.2 色彩与字体

使用 CSS 设计令牌锁定主色：

| 用途 | 色值 |
| --- | --- |
| 页面暖白 | `#FFF9F7` |
| 奶油粉底色 | `#FBE8EC` |
| 樱粉主色 | `#D96C8A` |
| 深梅色正文 | `#7B4051` |
| 薄荷绿正确态 | `#78BFA4` |
| 柔和边框 | `#EBCBD3` |

小号文字必须使用深梅色或更深颜色，交互文字与背景达到 WCAG AA 对比度。错误和正确不能只靠颜色表达，还要有文字和图形。

题目汉字使用清晰、规范的楷体优先字体栈，不使用手写体表现答案。拼音字号充足、声调清楚。输入框相关文字不得小于 16px，避免 iOS Safari 自动放大页面。

### 7.3 小桃猫吉祥物

设计一只原创、简洁的奶油色小猫 SVG，戴粉色小蝴蝶结，作为固定的品牌角色：

- 首页：在标题旁招手；
- 模式切换：用小幅表情提示当前模式；
- 答对：微笑并出现轻量星星动画；
- 判错：指向标准笔顺动画；
- 识别不清：露出疑问表情，提示再写清楚一点；
- 完成一课：展示成绩并进行鼓励。

小猫、猫爪和猫耳边角属于装饰层，不进入田字格，不影响笔迹坐标。图标和吉祥物随应用本地打包，不依赖外部图库。

### 7.4 动效

动效短促、柔和，不使用持续漂浮或干扰注意力的背景动画。遵循 `prefers-reduced-motion`；启用减少动态效果时，取消星星、弹跳和渐变动画，只保留必要的状态切换。

## 8. iPad 与 iPhone 适配

iPad 和 iPhone 使用同一套响应式页面和完整功能，不提供功能缩减的手机版。

### 8.1 iPad

- 横屏：左侧课目侧栏，右侧宽练习区；
- 竖屏：侧栏收起，可展开为抽屉；
- 田字格根据剩余空间放大并居中，适合 Apple Pencil 书写；
- 结果和笔顺动画与田字格并排或上下排列，避免横向滚动。

### 8.2 iPhone

- 课目选择使用全屏列表或底部抽屉；
- 练习区纵向排列：模式切换、拼音、田字格、操作按钮、反馈；
- 横竖屏均可用，旋转后保留当前字和归一化笔迹；
- 田字格优先占据主要宽度，按钮固定在安全区内，不能被底部 Home 指示条裁切。

### 8.3 触控与安全区

- 所有交互目标不小于 44×44 CSS px；
- 适配刘海、灵动岛、底部安全区和 Safari 动态地址栏；
- 使用动态视口单位控制页面高度，避免 iOS 地址栏伸缩造成按钮丢失；
- 不出现横向滚动；
- 用 Pointer Events 同时支持手指和触控笔，不依赖鼠标事件；
- 仅书写区域禁用触摸手势，其他区域保持页面自然滚动。

### 8.4 Safari 与主屏幕

- 支持 iOS/iPadOS Safari；
- 支持“添加到主屏幕”；
- 首次联网加载后缓存全部课程和笔画数据；
- 离线时可以继续认读、书写、播放设备自带读音并保存本机进度；
- iPad 与 iPhone 的 `localStorage` 互不相通，进度分别保存在各自设备。

## 9. 技术架构

### 9.1 技术栈

- React + TypeScript；
- Vite；
- Hanzi Writer：标准笔顺动画；
- Hanzi Writer 字符数据：目标字的标准笔画和轮廓；
- `vite-plugin-pwa` + Workbox：离线缓存与主屏幕安装；
- Vitest：单元测试；
- React Testing Library：组件流程测试；
- Playwright WebKit：iPad/iPhone 视口和触控流程测试；
- GitHub Actions：构建、测试和 GitHub Pages 发布。

不引入服务端、数据库、账号 SDK 或第三方统计脚本。

### 9.2 模块边界

```text
src/
  app/                 路由、页面外壳、全局错误边界
  content/             内容加载、分组查询、来源合并
  features/recognition/认读流程
  features/writing/    书写流程、来源选择、结果流程
  handwriting/
    capture             Pointer Events 笔迹采集
    transform           田字格与字符坐标转换
    stroke-matcher      单笔匹配
    character-evaluator 整字判定与错误分类
    thresholds          判定常量
  progress/            本地进度和最近练习
  audio/               系统语音播放与降级
  ui/                  设计令牌、按钮、卡片、小桃猫、笔顺播放器
  data/                构建生成的生产 JSON
```

每个模块通过明确的 TypeScript 类型通信。Handwriting 模块不得依赖 React，必须能在 Node 测试中独立调用。

### 9.3 数据生成

构建前使用脚本从核对后的教材条目和 Hanzi Writer 字符数据生成：

- `content.json`：31 个分组及全部练习条目；
- `characters/index.json`：413 个目标字的索引；
- `characters/{char}.json`：每个目标字的笔画数据。

生成脚本必须执行以下硬校验，任一失败即中止构建：

- 27 课、4 个语文园地、31 个分组；
- 识字表 265 条目、计数 250、多音字 15；
- 写字表 250 条目；
- 去重后 413 个目标字；
- 所有目标字均有笔画数据；
- 分组 ID 唯一，条目拼音非空；
- 语文园地插入顺序正确。

应用按当前分组按需加载字符数据。即使按需加载，PWA 构建仍预缓存完整的 413 字数据，保证首次联网完成后可离线使用。

### 9.4 本地存储

使用版本化 `localStorage`：

```ts
type StoredState = {
  schemaVersion: 1;
  contentVersion: string;
  settings: {
    defaultWritingSource: "writing" | "reading" | "both";
  };
  items: Record<string, {
    recognition?: {
      status: "known" | "review";
      attempts: number;
      lastPracticedAt: string;
    };
    writing?: {
      status: "correct" | "wrong" | "skipped";
      attempts: number;
      wrongAttempts: number;
      lastPracticedAt: string;
    };
  }>;
  recent?: {
    groupId: string;
    mode: "read" | "write";
    updatedAt: string;
  };
};
```

- 条目 ID 必须由分组、汉字和拼音稳定生成，不能依赖数组下标；
- 原始笔迹、截图、单笔匹配明细不进入本地存储；
- 存储无法读取或格式损坏时，提示后使用空进度继续，不能阻塞练习；
- 清理进度必须二次确认；
- 清除后同时移除最近练习和错字记录；
- 更新内容版本不自动清空旧进度，能匹配稳定条目 ID 的记录继续使用。

### 9.5 错误处理

- 课程数据加载失败：显示重试；离线时优先使用缓存。
- 单字笔画数据缺失：构建阶段应阻止发布；运行时若发生，书写项显示错误并允许跳过，不能错误判定。
- 语音不可用：显示提示，保留拼音和练习。
- 本地存储不可写：本次会话内继续使用内存状态，并提示刷新后进度可能丢失。
- Service Worker 更新：提示刷新以使用新版本，不在答题中强制刷新。
- 页面旋转或尺寸变化：保留已完成笔迹，不清空当前字和进度。

## 10. 部署与离线

### 10.1 GitHub Pages

- 默认使用公开 GitHub 仓库，以符合免费 GitHub Pages 的常见使用方式；
- 推送到主分支后由 GitHub Actions 执行测试和构建；
- 使用 `actions/configure-pages`、`actions/upload-pages-artifact` 和 `actions/deploy-pages`；
- 构建时注入仓库名作为 `base`，适配 `https://<用户>.github.io/<仓库名>/`；
- Hash 路由保证刷新练习页不会出现 404；
- 不要求 NAS、Docker、服务器运维或自定义域名。

### 10.2 PWA 与离线

- 提供 Web App Manifest、应用图标和小桃猫主题色；
- 支持 iOS/iPadOS“添加到主屏幕”；
- 预缓存应用外壳、31 个分组的数据和 413 个字符数据；
- 首次在线加载完成并激活 Service Worker 后显示“已可离线使用”；
- 离线时全部课目、认读、书写判定、笔顺动画、本地进度和可用的系统读音仍工作；
- 新版本发布时提示刷新，不能清除学习进度。

## 12. 测试与验收

### 12.1 数据测试

- 自动验证 27 课、4 个语文园地、31 个分组；
- 自动验证 265/250/15/250 的题目数量；
- 自动验证 413 个唯一目标字全部存在笔画数据；
- 自动验证语文园地插入顺序；
- 自动验证每个拼音非空、分组 ID 唯一；
- 自动验证“仅写字表 / 仅识字表 / 两表都有”的顺序、数量和去重结果。

### 12.2 判定测试

使用标准笔画合成测试样本，并加入至少 12 个覆盖不同笔画类型的真实或手工校准笔迹 fixture：

- 轻微抖动、平移、缩放和旋转在容差内的正确笔迹判为正确；
- 笔画顺序互换判为笔顺错；
- 笔画反向判为方向错；
- 缺笔、多笔或错误形状判为字形或笔画数量错；
- 随机涂画、单点触控、严重越界判为识别不清；
- 正确笔迹不得含错误原因；
- 判错结果必须能指向具体原因；
- 识别不清不得增加错误次数。

### 12.3 流程测试

- 认读：初始不显示拼音，点击后显示拼音和播放按钮；
- 书写：初始不显示目标字；
- 未落笔时提交按钮不可用；
- 写错后出现标准笔顺动画、“再写一次”和“先跳过”；
- 跳过字进入错字列表；
- 识别不清允许直接重写且不计错；
- 结果页正确数、错误数和错字列表与本次操作一致；
- 刷新后进度仍在；
- 一键清除进度需要确认并确实清空。

### 12.4 设备与离线测试

- Playwright WebKit 覆盖 iPhone 竖屏、iPhone 横屏、iPad 竖屏、iPad 横屏；
- 所有尺寸无横向滚动，田字格、按钮和反馈均在安全区内；
- 模拟 Pointer Events 完成整字书写和提交；
- 首次在线加载后断网刷新，课程、笔画数据和判定仍可用；
- GitHub Actions 构建产物部署到仓库子路径后可正常加载；
- 正式交付前在真实 iPad 和 iPhone 上分别用手指测试，iPad 另用 Apple Pencil 测试；
- 检查读音播放、系统减少动态效果、旋转、后台恢复和主屏幕启动。

### 12.5 完成标准

只有同时满足以下条件才算完成：

- 31 个分组和全部 413 个目标字可用；
- 三种书写来源结果正确；
- 字形、笔顺和方向错误都能被明确识别，无法确认时提示重写；
- iPad 与 iPhone 均能完成从选课到结果页的全部流程；
- 笔迹不上传，清理功能有效；
- 首次联网后可离线完成复习；
- GitHub Pages 网址可以直接在 iPad/iPhone Safari 打开；
- 第三方许可和教材来源声明完整。
